# משימה 8 — אימות פורמט הלוגים (בינארי חסכוני)

## הבעיה

נדרש לוודא שכל הלוגים המועלים לענן הם בפורמט **בינארי חסכוני ככל האפשר, ללא תווים מיותרים**, כדי לשמור
על גודל קטן בזיכרון ובהעברה.

> החלטת המשתמש: אופטימיזציה **צד-לקוח בלבד** — קבצי ה-edge function של השרת אינם ברפו, לכן לא משנים את
> חוזה השרת (כולל ה-base64).

## הביקורת

### 1. לוג אבחון `.kslog` — בינארי קומפקטי (כבר אופטימלי)

`SessionLogger` (iOS `Services/SessionLogger.swift`, Android `storage/SessionLogger.kt`) כותב פורמט בינארי
little-endian:
- **כותרת:** `KSLG` (4) + גרסה (1) + שמור (1) + אורך (uint16) + JSON מטא קצר.
- **רשומת דגימה ≈ 46 בייט:** type(1) + index(u32) + t_ms(u32) + 11×int16 (תאוצה/גירו/כבידה, מוקטן ×1000) +
  2×int32 (לחץ ברומטרי, מוקטן ×100) + speed(u16 ×100) + lowG(u16) + state(1) + אורך אירוע(u16) + מחרוזת.
- **רשומת אירוע ≈ 14 בייט.**
- כל מספר רב-בייטי little-endian; ערכים חסרים מקודדים כ-`Int16.min`/`Int32.min`. אין ריפוד מיותר.

**מסקנה:** הפורמט הבינארי כבר חסכוני מקסימלית בצד הלקוח. שינוי המבנה (למשל הסרת שדות) יחייב שבירת
ה-parser המקומי וה-decoder בשרת — מחוץ לתחום.

### 2. העלאת מדדי הסשן (`watch-ingest`) — JSON קומפקטי (כבר אופטימלי)

`WatchSessionUploader` (שתי הפלטפורמות) שולח JSON עם:
- **מפתחות קצרים** (`t,h,a,s,d,y,x` ב-jData; `durMin,jmax,jcnt,...`).
- **מספרים שלמים מוקטנים** (lat/lng ×1e4, גובה בס"מ, airtime בעשיריות שנייה).
- **השמטת שדות nil** (פרמטרים אופציונליים נשלחים רק אם קיימים).
- **ללא רווחים/pretty-print** (`JSONSerialization.data(withJSONObject:)` / ברירת מחדל).

**מסקנה:** אין "תווים מיותרים" בצד הלקוח.

### 3. אין CSV מילולי בסשנים חדשים

`SessionLogger` כותב כיום **רק** `.kslog`. ה-CSV נשמר לתאימות-לאחור (פירוק/רשימה של קבצים ישנים בלבד),
ואינו נוצר עבור סשנים חדשים — כך שלא מועלה לוג טקסטואלי מנופח.

## ה"עודף" היחיד שנותר — תלוי-שרת

`CloudSyncService` (iOS) עוטף את ה-`.kslog` הבינארי ב-**base64 בתוך JSON** (`contentEncoding: "base64"`),
תוספת של ~33%. הסרתה דורשת שה-edge function יקבל גוף בינארי גולמי (`application/octet-stream`) עם המטא
ב-query/headers (חלקם כבר נשלחים כ-`device`/`session`). מאחר שהשרת אינו ברפו וההחלטה היא צד-לקוח בלבד —
זה **לא בוצע** ומומלץ כ-Follow-up עתידי.

## תוצאה

לא נדרש שינוי קוד בצד הלקוח: כל הפורמטים כבר בינאריים/קומפקטיים מקסימלית במסגרת המגבלות שנבחרו. הביקורת
תיעדה את המבנים ואת ההזדמנות היחידה שנותרה (base64 → octet-stream), התלויה בשינוי שרת.

## מסקנות

- **kslog**: בינארי little-endian הדוק, ללא ריפוד — אופטימלי.
- **watch-ingest**: JSON עם מפתחות קצרים, ints מוקטנים, ללא רווחים, השמטת nil — אופטימלי.
- **אין CSV** בסשנים חדשים.
- **Follow-up מומלץ (שרת):** העלאת ה-kslog כ-`octet-stream` גולמי (ביטול base64, חיסכון ~33%) ואופציונלית gzip.
